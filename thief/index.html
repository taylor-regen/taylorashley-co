Step 1 of 7

What do you actually need?

Before you open Cursor, be honest about the job. Most people do not need a full ClickUp or Notion clone.

Pick what you are really paying for today:

  • Project management (tasks, deadlines, who’s doing what)
  • Scheduling content
  • Reporting
  • Tracking time
  • Getting approvals from clients or teammates
  • A mix of the above

Write that down in one sentence. The prompts below hang off that answer. If you only need a content calendar, do not brief an entire operating system.

Paste this into Cursor once you have your sentence. Swap the brackets for your words.
Prompt 
Help me turn how I work into a short product brief for a custom project management tool.

What I need it for: [one sentence from my list, e.g. task tracking and client approvals / content calendar only / personal projects]

I currently use: [ClickUp / Notion / Asana / Monday / something else / a mess of notes]

Features I actually use today:
- […]
- […]

People who need to see this tool: [just me / me + team / me + clients]

Ask me anything unclear. Then give me a short brief I can paste back into Cursor to start building. Keep it concrete. No buzzwords.

Step 2 of 7

Why I built mine

I was paying for a project management tool and mostly using it as a fancy to-do list. Same story if you are on ClickUp, Notion, Asana, Monday, whatever.

So I opened Cursor and built something that matches how my work already runs. Tasks. Statuses. Feedback on the thing itself. A calendar where that mattered. A way for people to log in and approve work without living in five tabs.

This guide is not “rebuild my exact app.” It is the path I used, with prompts you fill in for your work.

Step 3 of 7

The stack

The tools I used to build this project.

  • Cursor Where you build. You talk to it in plain English and it writes the app.
  • GitHub Where the code lives and gets versioned so you do not lose it.
  • Vercel Puts the app on the internet so you (and anyone else) can open it in a browser.
  • Supabase Logins, database and file storage. This is what I use. There are other options out there if you prefer something different.

For design, I looked at Behance, Pinterest and other SaaS products. I also used the tool I was already paying for as a functional reference: statuses, board feel, what I actually clicked every day. Do not rebuild every feature.

Step 4 of 7

Brief Cursor

This is the main bit. Paste the prompts. Fill in the brackets from step 1. When Cursor asks a question, answer it. When something is wrong, say which bit and correct it. You are steering the design and the build. This guide is just here to help you build yours and save some money.

Product brief

Start a new Cursor project (or an empty folder) and paste this as your first message.

Prompt 
Build me a simple project management web app that matches how I already work.

What it is for: [paste your one sentence from step 1]

I need these modules to start:
- [e.g. task board / to-do list / content calendar / approvals]
- […]

I do not need these yet (leave them out):
- [e.g. time tracking / reporting / chat / everything else]

Statuses I actually use, in order:
1. […]
2. […]
3. […]

Who uses it: [just me / me + [roles] / me + clients]

Tech I want:
- Next.js (or whatever you recommend for a simple web app)
- Supabase for logins, database and file uploads (or another backend if I prefer)
- Deploy-ready for Vercel
- GitHub-friendly project structure

Ask me clarifying questions before you scaffold. Do not invent features I did not ask for. Keep the first version small enough that I can use it this week.

Design direction

Once the skeleton exists, give it a look you can live with. Point at tools you already know.

Prompt 
Update the UI with this design direction.

Functional reference: [ClickUp / Notion / Asana / another tool I use]. Borrow the feel of [board / calendar / list view], not every feature.

Visual notes:
- Keep it clean and calm. No purple gradients. No generic AI-startup look.
- [Any colours, fonts or vibe I actually like]
- References I like from Behance / Pinterest / other SaaS: [describe or list links]

Make the main views usable on mobile. Prefer one clear layout over a dashboard full of widgets.

First build only

Force a small first version. You can add more later.

Prompt 
For this first version, only ship:
- [one main view, e.g. a status board]
- [optional second view, e.g. a simple to-do list]

Skip everything else for now. Make create / edit / status change / comments work well on those views. We will add more in later prompts.

Step 5 of 7

Logins (I used Supabase)

I used Supabase for logins, database and files. It is what worked for me. There are other tools out there if you want something different. Tell Cursor to wire logins properly instead of hacking local-only fake accounts.

If it is just you (or a small team)

Prompt 
Set up Supabase for this app (or another auth/database tool if I choose one).

I need:
- Email/password (or magic link) sign-in
- A simple way for me to create accounts for: [just me / these teammates: …]
- Each signed-in person only sees what they should see for their account
- Database tables for the modules we already built
- File uploads stored in storage if we need attachments or images

Walk me through creating the project and which keys go in .env. Do not put secret keys in the browser. Ask me anything you need before changing the code.

If you work with clients or customers

Ask them for, before you hand anyone a login:

  • Who needs access (names and emails)
  • What they are allowed to see
  • What they are allowed to approve or comment on
  • How you want feedback to land (on the item itself, not in a separate email chain if you can help it)
Prompt 
Add client / customer logins on top of the auth we set up.

People:
- Me / internal team: can see and edit [everything / listed areas]
- Clients: can sign in, see only their own workspace, and [approve / comment / view calendar] on items in [status names]

When I onboard a client I will have:
- Their name
- Login email(s)
- What they can see and approve

Build an invite or account-creation flow that matches that. Explain what I should ask the client for before I create their login. Do not let clients see other clients' work.

Step 6 of 7

GitHub and Vercel

Get the code somewhere safe, then put the app on the internet. Cursor and the Vercel dashboard will ask you questions. Answer them. There is not one perfect click-path for every machine.

Prompt 
Help me get this project on GitHub and deployed on Vercel.

I need:
- A clean git repo with a sensible .gitignore (no secrets, no .env)
- Steps to push to GitHub
- Steps to deploy on Vercel and connect the same GitHub repo
- Where to add my Supabase (or other backend) environment variables on Vercel
- How to confirm the live URL works for sign-in

Assume I am not a developer. Give me the exact commands and what I should click, and stop to check with me between stages if something can go wrong.

Step 7 of 7

Amend as you go

You do not need the perfect system on day one. Mine started as project management and picked up more as the work asked for it. This guide allows you to bend it as you see fit.

If a feature sits unused, cut it. If you need something new, add it.

Remove what you ignore

Prompt 
I do not use [feature / page / status]. Remove it from the app and the navigation. Keep the rest working. Do not leave dead links or empty tabs.

Add what you need next

Prompt 
I need to add [new thing, e.g. a content calendar / a simple report view / file attachments on tasks].

Requirements:
- […]
- […]

Wire it into the existing data model where it makes sense. Do not break [board / logins / whatever already works]. Ask questions before you build if anything is unclear.
